1. **Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?**  
   - **Git:** ветка — это просто указатель на коммит (ref). История — DAG неизменяемых объектов. Создание/переключение ветки — O(1), без копирования файлов.  
   - **SVN:** ветка — это копия директории в центральном репозитории. Даже при «cheap copy» на сервере это отдельное дерево, а операции переключения/слияния тяжелее и требуют связи с сервером.

2. **Можно ли в SVN сделать коммит без интернета? Почему?**  
   - **Нет.** SVN централизован: коммит всегда идёт на сервер. В рабочей копии нет локальной истории и возможности зафиксировать изменения автономно. Без сети можно только редактировать файлы, но не коммитить.

3. **В каких сценариях SVN до сих пор может быть предпочтительнее Git?**  
   - Нужен строгий централизованный контроль и тонкие права доступа по путям.  
   - Большие репозитории с бинарными файлами и частичным checkout (sparse/partial).  
   - Требуется блокировка файлов (lock) для избежания конфликтов.  
   - Простой линейный workflow для нетехнических пользователей.  
   - Интеграция с legacy-системами, где Git не поддерживается.  
   - Корпоративные среды с жёсткими прокси/политиками, где проще один сервер SVN.
